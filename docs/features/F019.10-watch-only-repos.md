# F019.10 — Watch-only library repos on /ci

> **Status:** built. Part of the F019 Deployment Management epic (observe / report / relay — upmetrics never executes).
> Promotes idea `019eb239` (2 confirmed consumers). Relates to F019.4 (CI watcher) + F019.5 (/ci viewer).

## Motivation

`GET /api/dashboard/ci` iterates projects `WHERE github_repo IS NOT NULL`. So a repo must be an **enrolled error/cost project** (carrying a DSN + api_key) to appear on /ci. Pure **library / infra repos with no runtime** — `broberg-ai/ai-sdk`, `broberg-ai/components` — have no errors and no agent-cost to ingest, so they can never be projects, and today the only way to surface their CI is a **hack project-row with an unused DSN/key**. Both sessions explicitly declined that (ai-sdk #4391/#4405; components #4545) and asked to be CI-visible the clean way.

## Scope

- A **config-driven watch-only repos list** (`owner/repo` strings, **no dsn/api_key**) that `/api/dashboard/ci` **unions** with the project-derived repos.
- De-duped: a repo that *is* an enrolled project keeps its project label and is not re-added as a library.
- Watch-only repos render with a `library` label (the existing /ci card shape, no UI change).

### Non-goals

- **No UI to manage the list** — v1 is a single-source config env (`WATCH_ONLY_REPOS`). A management surface is a separate story if ever needed.
- **No error/cost ingestion** for these repos — CI-observability only.
- **No deploy-relay** — pure libraries don't deploy (deploy-relay N/A).
- No new auth surface — the existing session-gated /ci route is reused unchanged.

## Architecture

- `config.watchOnlyRepos` — `WATCH_ONLY_REPOS` (comma-separated `owner/repo`), default `broberg-ai/ai-sdk,broberg-ai/components`. **Single source**, override via env; no value duplicated elsewhere.
- `ciTargets(projectRepos, watchOnly)` in `ci/github.ts` — **pure, unit-tested**. Builds the deduped `{repo, project}[]` target list (`project: 'library'` for watch-only). Project label wins on collision (case-insensitive repo match).
- `/api/dashboard/ci` maps each target through the existing `fetchWorkflowRuns` (60s cache, per-repo try/catch → one bad repo degrades only its card).

## Dependencies

- F019.4 `fetchWorkflowRuns` (reused as-is).
- `GITHUB_TOKEN` (classic PAT, scope repo) must be able to read both orgs' Actions — already true (the fleet token covers `broberg-ai/*`).

## Rollout

- Deploy `fly deploy -a upmetrics --ha=false`. The default list ships ai-sdk + components live immediately (no env needed). Verify on /ci (Lens) that both library repos appear with runs.

## Acceptance criteria

1. `/api/dashboard/ci` unions watch-only repos with project repos, de-duped (project label wins).
2. Watch-only list is config-driven (`WATCH_ONLY_REPOS`, single source) defaulting to the two confirmed consumers.
3. On prod /ci, `broberg-ai/ai-sdk` + `broberg-ai/components` appear with recent runs + a `library` label; a per-repo error degrades only that card.
4. `ciTargets` dedup is pure + unit-tested; full server tests + web build stay green.
