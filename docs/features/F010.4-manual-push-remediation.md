# F010.4 — Manual push-to-remediation + Remediation dashboard view

## Motivation
F010 (auto-remediation relay) only fires for **incidents** — correlation-opened error spikes (≥10 errors / 5 min) in high-severity, opted-in projects. A single ordinary issue (e.g. `TimeoutError`, 1 occurrence) never triggers anything. Christian, looking at an issue detail, asked: *“Hvis der ikke er auto remediation så skal der vel være et 'push' til det her?”* — and separately, that the relay loop had **no UI at all** (it ran fully auto; you couldn't see what had been sent to Buddy).

This story closes both gaps: an on-demand push, and a view of the loop.

## Scope
- **Manual push** from the issue detail modal: a `Push to remediation` button. Creates (or re-arms) an open `manual_remediation` incident keyed to the issue (`trigger_ref = issue.id`), `relay_requested_at = now`. Idempotent per open issue; if already claimed, no-op.
- **Bypass gates**: a manual push is explicit user intent, so it skips the auto severity threshold + per-project opt-in (`remediation_relay`) checks in `pendingRemediations`. `repo` falls back to `project.id` when `projects.repo` is unset. It still flows through the **same** `/api/remediation/pending` feed Buddy polls + claims — no new transport.
- **Remediation view** (`/remediation`, new nav item, Wrench icon): `Awaiting a session` (the live pending feed) + `History` (all relayed incidents — manual + auto — with the claiming session, manual/auto badged, timestamps).
- **Issues page fixes** (surfaced same session): a **Project** column (map `projectId→name`) so you can tell what belongs to whom, and reading `?project=` from the URL so the project-page deep-link filters correctly.

## Non-goals
- No approval/gate workflow (push is immediate). No per-issue policy config.
- No pageview/visit analytics (out of scope — this is error monitoring).
- Does not change the auto path or F005.3 HMAC webhook.

## Architecture
- **Schema**: migration `0004` adds `incidents.relay_requested_at` (timestamp_ms, nullable).
- **relay.ts**: `ERROR_KINDS` gains `manual_remediation`; `pendingRemediations` treats `relay_requested_at`-set incidents as eligible regardless of severity/opt-in; `RemediationItem` gains `manual: boolean`.
- **Endpoints** (`dashboard/routes.ts`): `POST /api/dashboard/issues/:id/push-remediation`; `GET /api/dashboard/remediation` (`{ pending, history }`).
- **Web**: `routes/Remediation.tsx` (+ nav + route); `Push to remediation` button + handler in `IssueDetail`; Project column + `?project=` read in `Issues`.
