# F020.3 — Dedicated SPM repo `broberg-ai/upmetrics-swift`

> **Status:** done. Splits the F020.1 package into its own SwiftPM repo so native apps consume it via `.package(url:from:)`, matching the `@broberg/*` fleet pattern (ai-sdk, components each = own repo).

## Why a dedicated repo (single source)

SwiftPM has no separate registry — it consumes **git source directly**. So unlike `@upmetrics/sdk` (source in the monorepo, built artifact published to npm), a Swift package's "published" form IS a git repo with a **root-level `Package.swift`**. Keeping the source in BOTH the upmetrics monorepo AND a distribution repo would be duplication → drift (violates the single-source rule). Therefore the **dedicated repo is canonical**, and the monorepo keeps only a pointer.

## What shipped

- **`broberg-ai/upmetrics-swift`** created (public), package at root, **tagged `0.1.0`**.
- **Proven consumable:** a fresh throwaway SPM consumer (`platforms: [.macOS(.v11)]`, `.package(url: "https://github.com/broberg-ai/upmetrics-swift", from: "0.1.0")`) resolved, built, linked, and ran — printing `resolved + linked upmetrics-swift OK`.
- **Monorepo single-source:** `upmetrics/packages/swift-sdk/` (the dev/verification copy from F020.1) is replaced with a `README.md` pointer to the canonical repo — no duplicated Swift source.
- **`buddy-mobile` project** created on upmetrics (separate from buddy-server so iOS crashes don't mix with server errors); its **public DSN** delivered to buddy over intercom (#5045) — public key, not a secret.

## Consumer (buddy mobile, via XcodeGen)

```yaml
packages:
  upmetrics: { url: https://github.com/broberg-ai/upmetrics-swift, from: "0.1.0" }
# target dependency: { package: upmetrics, product: Upmetrics }
```

## Non-goals / later

- **Automated re-publish on version bump** (a tag-sync from a source-of-truth) is NOT set up — v1 is a manual first publish. Since the dedicated repo is canonical, future edits happen THERE directly (then tag). If we ever want the source back in the monorepo, add a sync workflow (the npm-publish-on-tag analogue).
- Server-side dSYM symbolication = **F020.2**.

2. Monorepo `packages/swift-sdk` replaced with a pointer README (no duplicated source).
3. `buddy-mobile` project + public DSN created + delivered to buddy.
