# F016.1 — Lens mint-endpoint, delivered

Wrap-up story under epic **F016**. The epic carried its acceptance criteria directly and had no child story, so the board could not represent (or flip) the delivery. This story makes the delivered work visible and closeable. Full design lives in the epic plan-doc: [`F016-lens-mint-endpoint.md`](./F016-lens-mint-endpoint.md).

## What shipped (all 5 epic AC passed, evidence on the epic card)

- `POST /api/lens-session` — timing-safe `Authorization: Bearer LENS_MINT_SECRET`; missing/wrong/empty secret → `401` (endpoint disabled when the secret is unset). `auth/lens.ts`.
- `200` returns a Playwright `storageState` with one short-lived (10 min) read-only `upm_lens` cookie (a real Better Auth session for a synthetic `lens@upmetrics.org` principal — never `cb@`/admin).
- `requireUser` accepts the lens cookie on **GET only** — structurally read-only (any mutating method → `401`).
- `lens.manifest.json` auth = `{adapter:'mintEndpoint', url, secretPath:'.lens/mint-secret'}`; secret = `openssl rand -hex 32`, set as Fly secret `LENS_MINT_SECRET` + written to gitignored `.lens/mint-secret` (never over intercom).
- Tests: Bearer gate + cookie-shape + session accept/reject. Lens runtime-verified against prod via the mint adapter (run `f631f40a` = PASS, "MINT AUTHED+RENDERED").
