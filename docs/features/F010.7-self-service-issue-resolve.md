# F010.7 — Self-service issue list + resolve API

> Parent: [[F010]] closed-loop auto-remediation relay. Built 2026-06-03.

## Motivation

During the 2026-06-03 fleet error-sweep, every repo (trail, cardmem, cms, buddy)
asked upmetrics to **close their issues for them** — there was no headless path
(the dashboard is Better-Auth login-only). So the "fix → resolve → clean board"
loop always needed a human in the upmetrics UI. Completes the self-service surface
alongside cost-ingest (F014), remediation enrollment (F010.5), and the relay feed.

## Scope

- **`GET /api/issues`** (auth: project `X-Upmetrics-Key`) — list the caller
  project's issues. Default: unresolved only; `?status=` for an exact filter.
  Returns `{ project, issues:[{id,title,culprit,level,status,event_count,
  first_seen,last_seen}] }`.
- **`POST /api/issues/:id/resolve`** (same key) — body `{ status?: 'resolved' |
  'ignored' | 'unresolved' }`, default `resolved`. **404 if the issue is not the
  caller's project** — a project can never see or touch another project's issues.
- **UI:** the Issues-list `Project` column was a `Badge` pill that wrapped long
  names ("FysioDK Aalborg Sport") to 2 lines mid-pill — ugly. Drop the pill, render
  plain muted text (wraps cleanly, matches /remediation). `Badge` itself unchanged.

### Non-goals

- No bulk-resolve endpoint (one id at a time is enough).
- No new auth model — reuse the per-project api_key (cost/agent/enrollment).

## Architecture

`apps/server/src/issues/routes.ts` — `projectFromKey` (mirrors cost/agent), two
routes registered in app.ts. Cross-project isolation enforced by an AND on
`projectId` in every query. Tests share the `getDb()` singleton with the cost
route tests, so ids are namespaced `isr_*` to avoid collisions.
