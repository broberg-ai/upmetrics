# F010.5 — Self-service remediation enrollment (UI + API)

> Parent: [[F010]] closed-loop auto-remediation relay. Status: built 2026-06-03.

## Motivation

Remediation enrollment was **DB-only**: a project relayed auto-incidents to Buddy
only if its `projects.repo` + `remediation_relay` columns were set by hand (a
`fly ssh` + sqlite `UPDATE`). No UI, no API. Only `cardmem` and `buddy` were ever
enrolled. Christian: "Det burde være en toggle ... og lav et API så et repo kan
slå sig selv til/fra udefra."

Also surfaced: the relay severity gate (`REMEDIATION_RELAY_SEVERITY`, default
`high`) was a single GLOBAL env, so a project couldn't lower it — an everyday
`error_spike` is `medium` and never auto-relayed even when opted in.

## Scope

- **DB**: new nullable `projects.remediation_relay_severity` (migration 0007).
  `null` → inherit the global `config.remediationRelaySeverity`.
- **Self-service API** (auth = the project's own `X-Upmetrics-Key`, same key as
  cost-ingest): `GET /api/remediation/enrollment` reads, `PUT` sets
  `{enabled, repo, github_repo, severity}`. A repo enrols/disenrols itself.
- **Dashboard API** (session auth): `PATCH /api/dashboard/projects/:id/remediation`
  — SAME validate/write helpers as the key route (one source). `GET
  /api/dashboard/projects/:id` now returns the enrollment view.
- **UI**: an Auto-remediation card on ProjectDetail — custom `Toggle` (no native
  checkbox), repo input, severity `CustomSelect` (no native select), Save button
  with loading + dirty-guard + toast.
- **Relay gate**: `pendingRemediations` computes `minRank` per-project from
  `project.remediationRelaySeverity ?? config.remediationRelaySeverity`.

### Non-goals

- No per-project occurrence threshold (stays global).
- No change to Buddy's repo→session routing or the manual push-to-remediation
  path (manual still bypasses opt-in + severity).
- No new auth model — reuse `X-Upmetrics-Key` (repo) + Better-Auth session (UI).

## Architecture

Shared helpers in `apps/server/src/incidents/relay.ts`: `enrollmentView(project)`,
`buildEnrollmentPatch(body)` (validates severity ∈ {low,medium,high,critical} |
null, maps enabled/repo/github_repo), `applyEnrollment(db, id, patch)`. Both the
key route and the dashboard route call these → no drift. `projectFromKey` mirrors
the ingest/cost pattern.

## Dependencies

- [[F010]] relay feed + gate. [[F014]] established the `X-Upmetrics-Key` per-project
  auth pattern reused here.

## Rollout

migration 0007 → deploy → enrol `trail` via the API as the first live use
(`PUT /api/remediation/enrollment` with trail's key). Existing cardmem/buddy
enrollment is unchanged (columns already set).

## Acceptance criteria

See card AC. Live-verified by enrolling trail through the new endpoint and
confirming the enrollment view + that its incidents respect the chosen gate.
